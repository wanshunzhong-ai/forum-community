# 论坛社区网站 · 技术选型与开发清单

> 基于 **Python** 技术栈，面向 **中等规模社区**（数千 ~ 数万用户）的完整开发计划。
> 排期按 1 名后端全职估算，约 **11 ~ 12 周**；2 人协作可压缩到 7 ~ 8 周。

---

## 一、技术选型：为什么是 Python + Django

论坛是典型的「读多写少 + 强后台管理 + 权限复杂」型产品。

**Django vs FastAPI**：Django 自带 ORM、Auth、迁移、**Admin 后台**、权限系统。其中 Admin 直接省掉大半个运营后台开发量（版主审核、封禁、删帖、举报处理可先在 Admin 落地）。FastAPI 异步性能更好，但鉴权 / 后台 / ORM 都需自行拼装，更适合纯 API 服务。**从零做论坛 → 选 Django。**

### 推荐技术栈

| 分层 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.12+ | 与你的技术背景一致 |
| Web 框架 | Django 5.x | 全功能、生态成熟、自带 Admin |
| API（预留） | Django REST Framework | 为小程序 / App / SPA 预留接口 |
| 数据库 | PostgreSQL 16 | 支持全文检索、JSONB，比 MySQL 更适合社区 |
| 缓存 / 队列 | Redis 7 | 会话、热帖缓存、Celery broker |
| 异步任务 | Celery + Redis | 邮件 / 站内信 / 通知 / 索引更新 |
| 搜索 | Meilisearch（首选） | 轻量好部署，中文分词友好；量大再上 Elasticsearch |
| 前端 | Django 模板 + HTMX + Tailwind | 无需复杂前端工程，SEO 天然好，1 人可 hold |
| 富文本 | Markdown + 图片粘贴上传 | 论坛主流选择 |
| 对象存储 | 腾讯云 COS / 阿里云 OSS + CDN | 头像、图片附件 |
| 部署 | Docker + Nginx + Gunicorn | 单机起步，可横向扩展 |
| 监控 | Sentry + Prometheus/Grafana | 错误追踪 + 指标监控，上线必备 |
| CI/CD | GitHub Actions | 自动化测试 + 自动部署 |

**前端二选一**：
- 方案 A（默认推荐）：Django 模板 + HTMX —— 开发最快、SEO 好；
- 方案 B：Vue 3 + TS + Vite + Pinia —— 交互更好，需有前端伙伴。
- 选 B 时仅替换前端阶段，后端 API 层完全不变。

## 二、核心数据模型清单

| 模块 | 数据表 | 关键字段 |
|---|---|---|
| 用户 | `users_user`（扩展 AbstractUser） | 用户名、邮箱/手机、密码、头像、签名、角色、状态、注册时间、最后登录 |
| 用户 | `users_profile` | 昵称、性别、地区、积分、等级 |
| 用户 | `users_follow` | 关注关系（follower / following） |
| 版块 | `forum_category` | 名称、slug、描述、图标、排序、版主 |
| 版块 | `forum_board`（可选） | 所属板块、名称（分区） |
| 帖子 | `forum_thread` | 标题、作者、版块、标签、状态（正常/置顶/精华/关闭/删除）、浏览数、回复数、最后回复时间 |
| 帖子 | `forum_post`（回复） | 所属主题、作者、内容、楼层、引用帖、状态 |
| 帖子 | `forum_tag` | 标签名、slug |
| 互动 | `forum_like` | 用户、目标（帖子/回复）、类型 |
| 互动 | `forum_favorite` | 用户、主题 |
| 互动 | `forum_report` | 举报人、目标、理由、状态、处理人 |
| 通知 | `notify_notification` | 接收人、类型、内容、关联对象、已读 |
| 私信 | `message_conversation` / `message_message` | 参与者、内容、已读 |
| 运营 | `moderation_ban` | 用户、类型（禁言/封号）、原因、起止时间 |
| 安全 | `security_keyword` | 敏感词、级别、替换方式 |
| 系统 | `django_*` | 权限、会话、迁移等内置表 |

**关键索引**：`thread(板块, 置顶, 最后回复时间)`、`post(thread, 楼层)`、全文检索 GIN 索引。

## 三、开发里程碑与清单

### M0 · 需求与架构设计 —— 第 1 周
- [ ] 梳理核心功能边界（本期做什么 / 不做什么）
- [ ] 输出 ER 图（数据模型）
- [ ] 输出 API / 页面路由清单
- [ ] 确认技术选型与部署环境（服务器 / 域名 / 备案 / 对象存储）
- [ ] 原型草图（首页、版块页、帖子详情、个人中心）

> **交付**：设计文档 + 原型

### M1 · 项目脚手架与基础设施 —— 第 2 周
- [ ] 初始化 Django 项目结构（`config/` + 各功能 app）
- [ ] Docker Compose：PostgreSQL + Redis + Meilisearch
- [ ] 环境变量与配置管理（django-environ，区分 dev / prod）
- [ ] 自定义用户模型 `AUTH_USER_MODEL`（**必须在首次 migrate 前确定**）
- [ ] 代码规范（ruff / black / pre-commit）+ Git 仓库 + 分支策略
- [ ] CI 骨架（GitHub Actions：lint + test）

> **交付**：可 `docker compose up` 跑起来的空壳项目

### M2 · 用户系统 —— 第 3 ~ 4 周（1.5 周）
- [ ] 注册（邮箱/手机 + 验证码）、登录、退出、找回密码
- [ ] 第三方登录（微信 / QQ / GitHub，可选）
- [ ] 个人资料编辑、头像上传（对象存储）、修改密码
- [ ] 角色与权限：普通用户 / 版主 / 管理员
- [ ] 用户主页（发帖、回复、收藏列表）

> **交付**：可注册登录并维护资料的完整用户模块

### M3 · 版块与主题帖（核心）—— 第 4 ~ 6 周（2 周）
- [ ] 版块 / 分区管理（含版主配置）
- [ ] 发帖 / 编辑 / 删除 / 移动板块
- [ ] Markdown 富文本编辑器 + 图片粘贴上传
- [ ] 回复、引用、楼层、@ 提及
- [ ] 置顶 / 精华 / 关闭主题（版主操作）
- [ ] 列表分页、排序（最新 / 最热）

> **交付**：能完整走通「发帖 → 回帖 → 管理」的论坛主流程

### M4 · 互动与社交 —— 第 6 ~ 7 周（1.5 周）
- [ ] 点赞 / 收藏 / 关注（用户、主题）
- [ ] 站内通知（被回复 / 被 @ / 被点赞）+ 未读红点
- [ ] 私信（会话列表 + 消息）
- [ ] 举报入口（举报帖子 / 回复 / 用户）
- [ ] Celery 异步发送邮件 / 通知 / 索引进队列

> **交付**：互动闭环 + 通知系统

### M5 · 搜索与信息流 —— 第 7 ~ 8 周（1 周）
- [ ] 全文检索（Meilisearch 接入，标题 + 正文，中文分词）
- [ ] 标签系统 + 按标签筛选
- [ ] 首页信息流（最新 / 热门 / 精华）
- [ ] 热帖排行（Redis 计数 + 定时任务）

> **交付**：可搜索、可发现内容的社区

### M6 · 内容审核与安全 —— 第 8 ~ 9 周（1 周）
- [ ] 敏感词过滤（发布时拦截 / 替换 / 转审核）
- [ ] 内容机审（接入内容安全 API：文本 + 图片）
- [ ] 用户封禁 / 禁言 / 解除
- [ ] 举报处理后台（基于 Django Admin 定制）
- [ ] 反垃圾：频率限制、验证码、发帖冷却、IP 风控

> **交付**：具备运营审核能力的后台

### M7 · 前端完善与移动适配 —— 第 9 ~ 10 周（1.5 周）
- [ ] 页面完善：首页 / 版块 / 主题详情 / 个人中心 / 搜索 / 通知
- [ ] 响应式布局（移动端优先）、深色模式（可选）
- [ ] 组件化：帖子卡片、编辑器、分页、空状态、加载态
- [ ] SEO：语义化 HTML、meta、sitemap、SSR / 预渲染
- [ ] 无障碍与基础交互优化（HTMX 局部刷新）

> **交付**：体验完整、手机可用、可被搜索引擎收录

### M8 · 性能与稳定性优化 —— 第 10 ~ 11 周（1 周）
- [ ] 缓存策略：热帖 / 首页 / 版块列表缓存 + 缓存失效
- [ ] 数据库：慢查询分析、索引补齐、消除 N+1
- [ ] 静态资源 CDN、图片压缩与懒加载
- [ ] 分页 / 游标分页、接口限流
- [ ] 日志分级与结构化日志

> **交付**：可承载目标规模的性能基线

### M9 · 测试、部署与上线 —— 第 11 ~ 12 周（1 周）
- [ ] 单元测试 + 接口测试（核心流程覆盖率 > 70%）
- [ ] 压力测试（Locust / k6），记录 QPS 与瓶颈
- [ ] 生产部署：Nginx + Gunicorn + Docker，HTTPS 证书
- [ ] CI/CD 自动部署 + 灰度 / 回滚方案
- [ ] 监控告警：Sentry + Prometheus / Grafana
- [ ] 数据库自动备份 + 恢复演练
- [ ] 上线检查清单（域名备案、隐私政策、用户协议、robots）

> **交付**：正式上线并稳定运行的社区

## 四、执行说明

1. **关键前置项**（M1 必须先定，否则后期改造成本极高）
   - 自定义用户模型（`AUTH_USER_MODEL`）必须在首次迁移前确定。
   - 数据模型 / ER 图在 M0 定稿，后续只做增量。
2. **优先级**：M2 → M3 → M4 是「能用的论坛」最小闭环；时间紧张时 M5 ~ M8 可迭代上线。
3. **最小可跑通顺序**：脚手架 → 用户 → 发帖回帖 → 通知 → 上线。
